# Dashell RSS 本地开发版

更新：2026-10-04。候选版本：`2.7.2-dashell.1`。

## 本轮实现

直接在 RSS Dashboard 的 `dev` 源码上修改，仍使用原插件入口、订阅管理、
搜索、卡片首页、收藏、已读、保存和存储服务。

打开插件仍显示原 RSS Dashboard 的订阅树与卡片首页。点击订阅只筛选卡片，
Ctrl/Cmd 多选沿用原行为。点击文章卡片会准备正文、保存本地文件并直接打开
Dashell Reader；RSS 首页保留，不再为正常卡片操作打开第二套 RSS 阅读界面。
重复点击复用已有文件，保留用户修改和 Reader 阅读进度。原工作台代码暂保留，
但不再作为正常订阅和卡片的入口。

阅读主题、字体、查词、生词、朗读、AI 与复习配置由 Reader 负责。播客和视频
卡片沿用 RSS Dashboard 的原生预览、播放器和节目列表，不自动下载、不要求
启用 Dashell Player，也不显示额外的学习下载面板。
RSS 设置仍负责首页显示、订阅、下载目录和大小上限；常规设置的「媒体预览位置」
沿用既有阅读位置值，可选择分屏、左右侧栏、内嵌或外部浏览器。
学习衔接启用时，隐藏只服务文本的网页浏览器、已保存文章位置和阅读排版选项；
学习模块无法加载时仍保留原 RSS 阅读入口。

## 数据与文件

RSS Dashboard 管理订阅、已读和收藏。`dashell-learning.json` 单独管理资料的
本地文件关联、下载状态和学习轮次，每次写入前保存上一版 `.backup`。
写入串行，持久化成功才更新内存；未知 schema 或无效数据不会被默认值覆盖。

资源优先按服务器稳定 ID 关联，其次按文章链接，最后按频道与 GUID；同一
稳定 ID 跨频道复用一份本地资料。RSS 已读不等于学完，点击“完成本轮”才
确认完成，再次打开保留旧轮次并开始新轮次。RSS 不生成阅读或播放百分比。

普通正文经净化后保存为 Markdown。素材包必要文件全部成功才标记下载完成。
媒体和字幕使用相同的 `material` 文件名主干，另附来源笔记；失败清理本次
任务创建的文件，保留用户原有文件。

优先复用 RSS 已保存且仍存在的 Markdown 文件，不重新抓取或覆盖其中的笔记。
普通文章尝试提取更完整正文，网络或访问限制导致获取失败时可使用订阅已有正文；
完全没有正文时显示具体错误，不创建空资料。具有稳定素材 ID 且正文非空的精选
素材源直接使用其正文。重复点击合并准备任务，迟到任务不能覆盖后来选中的文章，
视图关闭或插件卸载后不再自动打开 Reader。

## 阅读版本协议

素材源提供的三个文本版本分别保存为 `文章标题.md`、`文章标题 - 译文.md`、
`文章标题 - 改写.md`。文件名过滤非法字符并限制长度，同标题资料由各自目录隔离。
每个版本的 frontmatter 包含相同的 `dashell_reader_versions`：

```yaml
dashell_reader_versions: {"version":1,"id":"material-id","title":"Article title","original":"Article title.md","translation":"Article title - 译文.md","rewrite":"Article title - 改写.md"}
```

缺少的版本不写入清单。Reader 只接受同目录的安全 Markdown 文件名，拒绝任意路径；
仍能读取旧的固定文件名清单。Reader 自动创建阅读笔记时优先使用清单中的文章标题。
解析也支持 Obsidian 属性编辑器展开后的 YAML。多个版本存在时，Reader 顶栏
显示原文、译文、改写选择。切换前保存当前阅读位置，每个文件保持自己的进度。
再次从 RSS 打开时，Reader 按自身最近阅读时间恢复版本，RSS 不复制阅读进度。

RSS 调用 Reader 的 `openLearningMaterial(file)`；旧版 Reader 仍可通过其已有
`openFile(file)` 打开原文，但不具备自动选择最近版本的能力。Reader 返回失败时
保留下载文件并提示，不标记学习开始。两个插件仍独立构建、安装和维护。

## 素材源扩展

普通 RSS/Atom/JSON Feed 无需改造即可继续订阅。学习资料可附加以下数据：

- RSS/Atom 命名空间：`https://dashell.app/rss/1`。
- JSON Feed 扩展对象：`_dashell`。
- 字段：`id`、`language`、`level`、`translation`、`rewrite`、`assets`。
- 资产：`url`、`role`（main/subtitle/transcript）、`extension`、`required`、可选 `bytes`。
- 一个素材包只允许一个主文件，目标文件名不得重复；链接限定 HTTP(S)，
  无用户名密码，文件类型采用允许名单，下载路径限定库内。

只显示素材源实际提供的译文和改写，不把这些版本冒称为客户端实时 AI 生成。

## 本轮边界

首页、订阅管理、订阅树和首页卡片仍由 RSS Dashboard 提供；阅读和学习在
Reader/Player 中进行。打开文章是否自动标记已读遵循原设置。
没有把 Qiaomu 的全部服务、精选、摘录、日记和导出系统整体搬入。

本地候选使用独立技术 ID `dashell-rss`，安装到指定库的独立插件目录。
首次启用复制旧 `rss-dashboard` 中的设置、分片、文章状态、学习记录和备份；
只重写旧插件目录内部的存储路径，用户自定义库内目录保持原样。
写入成功后记录一次性迁移标记；冲突、无效设置或复制失败会停止启动，
避免在部分迁移数据上继续写入。原目录保留，可停用新插件后启用旧插件回退。
旧 `obsidian://rss-dashboard` 订阅链接仍受支持，测试库只启用一个 RSS 插件。
后续从 Dashell 自身构建更新；上游社区更新不再直接覆盖定制插件。

本轮按固定发布标签 `2.7.1` 选择移植“管理订阅”浅色主题按钮文字修复，
并补充并发重复订阅保护；没有整体合并上游新的 `dev` 或改动 Dashell 的阅读衔接。

尚未实现：按水平的专用学习筛选、独立在学页、用户账户、支付、服务器目录、
实时 AI 处理、Qiaomu 服务接口连接、OCR、ASR、任意视频网页抓取及断点续传。

`requestUrl` 会把响应缓冲到内存，大小检查在响应返回后执行；取消或超时
不会中止已经发出的网络传输，但取消后不会继续写入资料文件。

## 开发和验证

在源码目录执行 `npm ci`、`npm run build`、`npm run test:unit`。
宿主检查只在用户指定库进行，脚本用注册 ID、实际路径、配置目录和进程
共同验证身份。安装器备份原插件和工作区；测试资料使用明确 QA 名称。
私有备份、真实库配置和完整工作区信息保存在库外，不提交到 Git。
